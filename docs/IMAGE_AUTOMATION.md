# GPT 세션 이미지 작업 — 몫 없이, 잠금만

pkm-atelier 의 `docs/IMAGE_AUTOMATION.md` 를 원소 꼴로 옮긴 것이다(game · book 과 같은 길 — 사용자 2026-10-31 「pkm 공방처럼 gpt용 이미지 생성룰을 book, game, element 공방에도 정의해줘. 일상컷은 각 캐릭별 5장으로」).
사람이 지켜보지 않는 GPT 세션이 빈 카드를 차례대로 채우는 길이다. 사람이 지켜보는 세션은 `IMAGE_RULES.md` 그대로 한다(「올릴까?」).
원소의 한 카드 = **사는 세계마다** 세계 그림 한 장 + 그 세계 그림을 붙인 **일상컷 다섯 장**(사용자 2026-10-31 「세계마다 다섯 장」).

## 0. 승인 — 묻지 않고 올린다 (사용자 2026-10-31)

사용자가 pkm 처럼 정했다: **중간에 묻지 않고, AI 검수(QA) 뒤 바로 올린다. 그림의 시각적 품질은 올라간 뒤 사용자가 본다.**
그래서 GPT 세션에서는 `IMAGE_RULES.md` 1절의 다음 둘이 바뀐다.

| IMAGE_RULES(1절) | GPT 세션 |
|---|---|
| 올리기 전에 사람이 본다 — 「올릴까?」 | 묻지 않는다. 아래 4절 검수를 적고 올린다 |
| 계획대로 안 나오면(메카가 드레스로, 물건을 손에 든 채) 원인을 적어 먼저 묻는다 | 묻지도, 고쳐 다시 그리지도 않는다. 어긋난 데와 원인을 검수 기록에 적고 올린다 |

이 승인이 닿지 **않는** 것 — 그때는 그 자리에서 멈추고(5절 block) 보고한다:
안전 필터 거절이 1절 순서(같은 지시문 한 번 → 노출 한 단계씩 → 계획 바꾸기 한 번)를 다 밟고도 남을 때, 결과가 불분명한 응답, 원본을 잃음, 도구 오류,
다른 세션의 잠금, 받은 그림이 1024×1536 이 아님(한 번 더 — 그래도 아니면 멈춤), 이미 있는 파일 이름.
그 원소의 기호와 원자 번호가 읽히는 것은 걸림이 아니다(사용자 2026-10-31 — 저작권 문제가 없는 공방이라 허용, `IMAGE_RULES.md` 1절).
이미 올라간 그림을 덮거나 지우는 일, 강제 push, 이력 재작성은 어떤 경우에도 하지 않는다.

## 1. 준비

- `AGENTS.md` · `IMAGE_RULES.md` 를 먼저 읽는다. 코드(`element-atelier`)와 그림(`element-atelier-img`) 저장소를 **나란히** 받아 최신 `main` 으로 둔다.
  남의 로컬 변경을 reset 하지 않는다.
- Node 와 Python 3 + Pillow 가 있으면 된다. **브라우저는 쓰지 않는다** — 생성기 화면 대신 지시문 묶음(`tools/prompt-pack.cjs`)이 같은 글을 파일로 준다
  (`tests/prompt-pack-screen.cjs` 가 세계 그림 · 일상컷 자리를 실제 화면과 글자 하나까지 견준다).
- 실행 ID 를 **한 번** 정하고 이 실행의 모든 명령에 그대로 쓴다. 부모 작업이 준 호출 ID 가 있으면 그것.

```sh
export ATELIER_EXECUTION_ID="element-$(date -u +%Y%m%dT%H%M%SZ)"
node tools/image-claim.cjs status                      # 잠금 · 오늘 쓴 몫 · 다음 차례(읽기만)
```

`status` 에 「빈 자리 없음 — done 으로 끝낸다」 가 붙은 잠금이 있으면 그것부터 `done` 한다(앞 실행이 등록을 기다리다 끝났다 — 6절).

## 2. 차례와 잠금

```sh
node tools/image-claim.cjs next                         # 다음에 그릴 카드와 빈 자리
node tools/image-claim.cjs claim <카드> --execution $ATELIER_EXECUTION_ID
```

- 차례는 도감 차례(나라 → 가문주 → 주민, 설계표 차례)다 — 나라 하나를 끝까지 그린 뒤 다음 나라로(`IMAGE_RULES.md` 2절). 고르는 것은 도구가 한다.
- **하루 · 실행마다의 몫이 없다**(사용자 2026-10-31 「원소공방 저장소 이미지 저장 제한 없애줘」 — 그 전에는 실행마다 한 카드 · 하루 열두 카드였다). 한 실행이 여러 카드를 차례로 잡아도 된다.
  잠금은 그대로다 — 다른 세션이 잡은 카드는 건드리지 않고, 한 카드를 끝내거나 멈춘(block) 뒤 다음 카드를 잡는다. 그림 저장소가 900 MB 를 넘으면 썸네일 워크플로가 경고한다(Pages 1 GB) — 그때는 다음 그림 저장소를 연다(`IMAGE_RULES.md`).
- 잠금은 그림 저장소 `records/automation/claims/<카드>.json` 하나다. `claim` 은 그 파일만 커밋해 일반 push 한다 —
  다른 세션이 먼저 밀었으면 거절되고 도구가 제 커밋을 되돌린다. 그때는 pull 하고 `status` 부터 다시.
- 잡힌 카드(`working` · `blocked`)는 시간이 지나도 가져가지 않는다. `blocked` 는 사용자가 정한 뒤 `release` 로만 푼다.
- 한 카드의 빈 자리 = 사는 세계마다 세계 그림 · **일상컷 다섯 장**(기본 화풍 `game_keyart`, `data/img.json`). 다섯보다 적은 옛 카드(철나라 · 수소나라 두 장, 오가네손 세 장)는 모자란 만큼만 더 그린다.
  번호는 **세계마다 따로** 비어 있는 가장 작은 것부터 — 이름에 세계가 있어 세계끼리 번호가 겹쳐도 된다(`claim` 이 적어 준 `missing` 그대로).

## 3. 계획과 지시문 묶음

작업 폴더(`$W`)는 세션 임시 자리에 둔다. 일상컷이 빈 세계마다 계획부터:

```sh
node tools/casual-plan.cjs <카드> --world <세계> --records ../element-atelier-img/records/<카드> --out $W/plan-<세계>   # --slots 를 안 주면 그 세계의 빈 번호
node tools/prompt-pack.cjs init <카드> --dir $W/pack --plan $W/plan-fantasy/plan.json --plan $W/plan-steampunk/plan.json …   # 계획한 세계만
node tools/prompt-pack.cjs build --dir $W/pack                                  # 자리마다 <자리>-prompt.txt · <자리>-ui.json · INDEX.md
```

- 일상컷은 **트리 버전2**(game 의 `docs/CASUAL_TREE_V2.md`)로 짠다. 계획기가 세계 묶음 규칙(필수 갈래 · 네 시대 · 먼/가까운 컷 · 그 원소의 물건 한두 장 · 소품 고르게 · 카드 사이 안 쓴 장소 · 옷 · 자세 · 표정 먼저 …, `IMAGE_RULES.md` 2절)을 지킨다. 그림 저장소 기록을 읽어야 하니 `--usage none` 은 쓰지 않는다.
  GPT 세션은 계획을 사람에게 보이지 않는다 — 계획기 출력 그대로 간다. 이미 있는 컷의 기록(`--records`)은 겹침 검사에만 쓴다.
- `settings.json` 은 **비워 둔 채** build 하는 것이 기본이다. 고칠 때만 칸을 채우고, 직접 입력(덧붙임 글 · 표에 없는 외형)엔 `why` 를 적는다.
  틀린 칸이 하나라도 있으면 build 가 아무것도 안 쓴다. 고칠 수 있는 칸은 `tools/prompt-pack.cjs` 머리말에.
- **`<자리>-prompt.txt` 를 손으로 고쳐 내지 않는다.** 고칠 것이 있으면 settings 를 고쳐 build 를 다시 돌린다.
- 이미지 도구가 일상 한 칸을 막아(같은 지시문 두 번 · 노출 보통 · 적게까지 다 막혀 — `IMAGE_RULES.md` 1절) 다시 정할 때는 그 칸만 `--slots N --seed <다른 씨앗>` 으로 계획기에 다시 맡기고
  `--records` 에 나머지 기록을 준다 — 그것도 한 번만. 새 계획에서도 같은 지시문 한 번 · 노출 낮추기를 밟고, 다시 막히면 5절.
- 올리기 전에 `node tools/casual-plan.cjs <카드> --world <세계> --check <이 카드의 기록 폴더>` 가 통과해야 한다(새 기록을 넣은 사본으로 본다).

## 4. 그리기와 검수

- `INDEX.md` 의 차례대로, **`claim` 의 `missing` 에 있는 자리만** 그린다. 자리 하나에 생성 호출 한 번.
- 세계 그림은 **기준 그림 없이** 한 장씩(세계마다 다른 사람이다). 일상컷은 그 세계 그림을 **꼭** 붙인다(이미지 편집 — 첨부 없이 뽑으면 다른 사람이 된다).
  이 세션에서 받은 원본, 이미 등록된 세계 그림이면 그림 저장소의 `img/<파일>.webp`. 세계 그림이 없는 세계는 일상컷을 그리지 않는다.
- 이미지 도구에 크기 설정이 있으면 1024×1536 으로 준다. 도구가 실제로 돌려준 파일만 쓴다.
- 받은 뒤 **AI 검수**를 적는다(기록의 `qa` — 7절). 본 것을 구체적으로:
  1024×1536 인가 · 화풍이 2.5D 인가(평면 셀 2D 애니 얼굴 · 스케치로 나오지 않았나 — 화풍 v3, 2026-11-02 · 반실사 · 에어브러시 · 3D 렌더 얼굴로 넘치지 않았나 — 화풍 v4d, 2026-11-03) · 그녀 한 명(배경 흐린 사람은 괜찮다) · 그 원소의 기호 · 원자 번호 말고 읽히는 글자·숫자(낱말 · 이름 · 다른 숫자 · 눈금 숫자 — 기호 · 원자 번호는 괜찮다) · 로고 · 워터마크 · 그림에 틀 ·
  세계 그림이면 고른 세계(판타지 · 스팀펑크 · 메카)대로인가, 주민이 물건을 손에 들지 않았나(모티브로만 — 입는 물건은 입은 그대로) ·
  일상컷이면 첨부한 세계 그림과 같은 얼굴 · 머리 · 몸인가, 첨부의 옷 · 갑옷을 가져오지 않았나, 계획 칸(시대 · 장소 · 의상 · 프레이밍 · 몸·머리 방향 · 두 손 · 소품 동작)대로인가,
  원소 성질을 옷의 색 · 무늬로 옮기지 않았나 · **팔·다리·손의 수와 이어짐**.
- 검수에서 걸린 것은 `passed: false` 와 함께 그대로 적고 **올린다**(0절 승인 — 사용자가 올라간 뒤 본다). 다시 그리지 않는다.
  지시문에서 부딪힌 줄(세계 · 장소 · 의상 · 자세 · 프레이밍 · HAND · ANGLE · WARDROBE · 시대)을 찾았으면 원인도 적는다 — 규칙 · 계획기를 고치는 일은 사람이 지켜보는 세션이 한다.

## 5. 멈춤

```sh
node tools/image-claim.cjs block <카드> --execution $ATELIER_EXECUTION_ID --reason '실제 까닭(어느 자리 · 무슨 응답)'
```

- 0절의 「닿지 않는 것」 이면 그 자리는 그리지 않고 block 한다. 그 전까지 검수한 자리는 6절대로 올려도 된다(빈 자리를 줄인다).
- 거절된 지시문은 sha256 과 함께 기록 폴더에 `<자리>.blocked.json` 으로 남긴다(지시문 · 시도 수 · 응답 코드). 그 지시문을 바꿔 다시 시도하지 않는다.
- block 된 카드는 사용자가 정할 때까지 잠긴 채다. 사용자가 정하면 사람이 지켜보는 세션이 `release --approval '<사용자 말>'` 로 푼다.

## 6. 올리기와 끝

1. 자리마다 원본을 WebP(품질 90, method 6, 1024×1536)로 바꾼다. 이름은 `INDEX.md` 의 「올릴 파일」(= `IMAGE_RULES.md` 3절). 같은 이름이 그림 저장소에 이미 있으면 멈춘다 — 덮지 않는다.
2. 그림 저장소에 **한 카드 한 커밋**으로 일반 push 한다: `img/<파일>.webp` 들과 `records/<카드>/` 의 기록 —
   세계 그림은 `<세계>.<화풍>-ui.json`, 일상컷은 `<세계>-casualN.<화풍>-ui.json`(묶음의 `<자리>-ui.json` 을 이 이름으로 — 안의 `record` 칸이 그 자리다), 일상 계획은 `<세계>-casual-plan.json`.
   기록 JSON 에 7절의 `generation` · `qa` 칸을 더한다. **원본 PNG 는 올리지 않는다** — sha256 만. 썸네일 · `data/img.json` 은 손으로 만들지 않는다(워크플로가 한다).
3. push 가 밀리면 pull --rebase 한 번. 그 사이 같은 파일 이름이 들어왔으면 멈추고 보고한다.
4. 그림 저장소 Actions 의 `썸네일` 이 초록인지, 코드 저장소에 `그림 등록` 커밋이 생겼는지 본다(토큰이 없으면 한 시간마다 돈다).
5. 코드 저장소를 pull 한 뒤 끝낸다. 등록이 아직이면 잠금을 `working` 으로 두고 실행을 마친다 — 다음 실행의 `status` 가 끝내라고 알려 준다.

```sh
node tools/image-claim.cjs done <카드> --execution $ATELIER_EXECUTION_ID
```

`done` 은 `data/img.json` 에 그 카드의 빈 자리가 없어야 된다(사는 세계마다 세계 그림 + 일상컷 다섯 장).

## 7. 기록에 더하는 칸 — `records/<카드>/<…>-ui.json`

묶음이 쓴 기록(생성기 「기록 내보내기」 꼴 + `record` · `storage`)에 올릴 때 더한다:

```json
{"generation": {"tool": "image_gen (GPT 세션)", "endpoint": "images/generations | images/edits", "ref_sha256": "<일상컷 — 붙인 세계 그림의 sha256>",
                "size": [1024, 1536], "png_sha256": "<원본>", "webp": {"quality": 90}, "note": "원본 PNG 는 올리지 않는다 — sha256 만 남긴다"},
 "execution": "<실행 ID>", "imported": "<YYYY-MM-DD>",
 "qa": {"reviewer": "<세션>", "image_sha256": "<원본>", "passed": true, "observations": ["<본 것 하나씩>"], "cause": "<어긋났으면 부딪힌 줄>"},
 "acceptance": "user_approval_2026-10-31 — 묻지 않고 올리고 사용자가 올라간 뒤 본다"}
```

## 8. 하지 않는 것

- 브라우저로 생성기를 조작하지 않는다 · 다른 유료 API 나 새 자격증명을 쓰지 않는다 · 계획 · 지시문을 손으로 고쳐 내지 않는다.
- 남의 잠금 · 기록 · 그림을 고치지 않는다 · 검수 실패를 통과로 바꾸지 않는다 · 같은 자리를 여러 번 다시 그려 고르지 않는다 · 화풍을 바꾸지 않는다(늘 기본).
